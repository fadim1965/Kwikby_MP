Can we select a user with decrypted password from SQL Query?
No. The PasswordHash column stores a one-way PBKDF2 hash (iterations.salt.derivedKey). There is no key to decrypt it, and SQL Server has no built-in PBKDF2 function, so you cannot reverse it with a query.

What you can do
Goal	How
Know a working password	Use the seeded test accounts: admin@api.test / Admin#12345, vendor@api.test / Vendor#12345 (scratch DB only)
Verify a candidate password	Call POST /api/v1/auth/token (returns 200 + token on success, 401 on failure) or use IPasswordHasher.Verify in C#
Reset a password	Re-run ./Database/06_SeedApiTest.ps1 (regenerates hashes) or update PasswordHash with a freshly generated hash
Generate a hash for a new password	Use the New-PasswordHash function in 06_SeedApiTest.ps1 (PBKDF2, 210,000 iterations, SHA-256)
Example: reset a user's password via SQL
# 1. Generate a hash in PowerShell
. .\Database\06_SeedApiTest.ps1  # loads New-PasswordHash
$hash = New-PasswordHash 'MyNewPassword#1'
Write-Host $hash
-- 2. Apply it
UPDATE dbo.Users
SET PasswordHash = N'<paste hash here>',
    AccessFailedCount = 0,
    LockoutEndUtc = NULL
WHERE Email = 'admin@api.test';
The hash format is 210000.<base64 salt>.<base64 key> — the salt is random per call, so the same password produces different hashes each time.

How to display in plain text User Password in SQL?
You cannot. Passwords are not stored in plain text — they are stored as a one-way PBKDF2 hash. There is no SQL function (or any function) that can convert a hash back into the original password.

Why
The PasswordHash column contains something like 210000.<base64 salt>.<base64 key>.
PBKDF2 is a key-derivation function, not encryption. It is deliberately irreversible.
Even with full database access, an attacker can only try to guess passwords by hashing candidates and comparing — which is exactly what the login endpoint does.
What you can do instead
What you want	How
Know a working password	Use the seeded test accounts: admin@api.test / Admin#12345, vendor@api.test / Vendor#12345
Test a password	POST /api/v1/auth/token with { "email": "...", "password": "..." } ? 200 = correct, 401 = wrong
Reset a forgotten password	Generate a new hash and UPDATE dbo.Users SET PasswordHash = ... (see below)
See who has a weak password	You can't — you'd have to brute-force against the hash offline
Generate a new hash (PowerShell)
# Re-use the seeder's function
. .\Database\06_SeedApiTest.ps1
$hash = New-PasswordHash 'MyNewPassword#1'
$hash
Apply it
UPDATE dbo.Users
SET PasswordHash = N'<paste the hash here>',
    AccessFailedCount = 0,
    LockoutEndUtc = NULL
WHERE Email = 'admin@api.test';
If you need a user's password for support/debugging, the correct process is a password reset (send a reset link / set a temporary password), never reading the stored hash.
